LEARN BY TALKING

先搞懂它是什么，再点按钮。

这是一条有状态的双向 WebSocket：你可以边说边听，也可以只让它打字幕。顶栏三页不能混用。Live 不是万能接口：不是 Chirp，不是 Cloud TTS，不是会议纪要，也不是双向视频通话。

官方定位：Live = 1 对 1 实时会话，不是语音需求的统一入口

对话：你说，它说（可打断，可选 JPEG 1fps）。听写：你说，它只打字幕，不接话。打字：你打字，它说——和对话同一条长连接，差别主要是输入方式。点停止才挂断。

不要用 Live 提：一小时会、说话人分离、电话/医学 ASR、SSML 配音、要模型回传画面、离线/克隆声纹。

它能干嘛

语音助手、近实时字幕、先打字再听它说。对话页可以打断、开摄像头或共享屏幕（JPEG 1fps，它只看不回传画面），也可以试会话恢复、压缩、演示函数、搜索接地和原生音频开关。

三页分别是谁

「对话」= 原生音频 GA，麦克风进、语音出。「听写」= 3.5 Transcribe Live，只要字幕。「打字」= 同一套对话模型，文本进、语音出，长连接多轮发送。

先做这三件事

① 打字页请模型说 → 改字再发一句 → 停止才挂断
② 听写页点开始听写，对着麦克风说话
③ 对话页说「你好」，再说到一半打断它；可选打开摄像头

核查日期 2026-09-10。Live 不是 Chirp 的替换件。对话页 SpeechConfig 语言表没有普通话。

三个工作台怎么选？

先对场景，再进对应页。样例不会跨页。

对话 / 字幕 / 打字

这不是三个模型家族那么简单：听写页换了模型 ID 和区域；打字页和对话页是同一个原生音频模型。

GCP Live、Gemini API Live、Chirp 流式

本 Demo 只走 Vertex + ADC。API Key 那条 Live、Speech-to-Text 流式都不是这个按钮。

什么时候不选 Live？

电话、医学、批量、合同级 GA 听写，请回 Speech-to-Text。

业务怎么选型？

定价以官方价目为准。Preview 模型会变。

每个开关的业务价值
